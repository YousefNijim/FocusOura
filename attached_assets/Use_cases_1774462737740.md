## Use Case 1: Start Focus Session

### Actor
Student (Authenticated User)

---

### Description
Allows a student to start a focus session for a selected subject using a specific session type.  
The system validates the request, enforces focus restrictions, and begins tracking session events.

---

### Preconditions
- User is authenticated
- Subject exists and belongs to the user
- No active focus session is currently running

---

### Trigger
User taps the "Start Focus Session" button

---

### Main Flow

1. User selects:
   - Subject
   - Session type (Routine / Homework / Deep Focus)

2. System validates:
   - Subject ownership
   - Session configuration validity

3. System loads:
   - Subject–Plant mapping from database

4. System initializes a new session with state `initialized`

5. System activates focus restrictions via Device OS:
   - Based on session type

6. System starts the session timer

7. System changes session state to `started`

8. System records session start event

---

### Postconditions
- A new session is active
- Session state is `started`
- Initial session event is stored
- Lock protocol is enforced

---

### Alternate Flows

#### A1 – Invalid Subject
- System rejects request
- Displays error message
- No session is created

#### A2 – Lock Activation Failed
- System aborts session
- Session state is set to `aborted`
- Abort event is recorded

---

### Data Written
- `sessions`
- `session_events`

---

### Data Read
- `subjects`
- `plants`

---

## Use Case 2: Track Focus Session Events

### Actor
System (Automatic)

---

### Description
Tracks session-related events such as warnings, violations, and state transitions.

---

### Main Flow

1. Timer emits periodic updates
2. Lock system reports violations (if any)
3. System records events:
   - Warning
   - Violation
   - Abort (if threshold exceeded)

---

### Data Written
- `session_events`
